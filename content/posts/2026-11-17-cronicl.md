# Why

I've been putting together our family tree, and I've tried a few tools along the way, including [webtrees](https://www.webtrees.net/). webtrees does a lot and it works, but it's a PHP app with a database behind it. That means user accounts, backups of a database and its uploads, testing that a restore actually works, and keeping up with security updates for something that's sitting on the internet. That's a lot of upkeep for a family tree that changes a few times a month.

I wanted fewer moving parts: the tree in a file I could open in a text editor, keep in git, and still read in twenty years without the program that wrote it. Backing it up should just be pushing the repository somewhere. And sharing it with family should be a folder of static files, with nothing running on a server that needs patching. I didn't find anything like that, so I wrote [cronicl](https://github.com/cbenning/cronicl).

# The file

The whole family lives in one YAML file, `family.yml`. Each person is a block keyed by an id, and a couple is two ids joined with a `+`:

```yaml
byron-george:
  name: {given: George, surname: Byron}
  birth: {date: 1788-01-22, place: "London, England"}
  death: {date: 1824-04-19, place: "Missolonghi, Greece"}

milbanke-annabella:
  name: {given: Annabella, surname: Milbanke}
  birth: 1792-05-17

byron-george + milbanke-annabella:
  events:
    - {type: marriage, date: 1815-01-02, place: "Seaham, England"}

lovelace-ada:
  name: {given: Augusta Ada, surname: Lovelace}
  birth: {date: 1815-12-10, place: "London, England"}
  parents: [byron-george, milbanke-annabella]
```

Finding someone is a text search. Renaming an id is a find-and-replace (or `cronicl rename`, which also catches the couple keys). When the file gets too big you can split it into a folder of files, one per branch or however you like.

The format is written down in a [spec](https://github.com/cbenning/cronicl/blob/main/SPEC.md), with a JSON Schema and a conformance test suite, so another tool could read and write the same file. That was more work than the code in some places, but it's the part I care about most: the data shouldn't depend on cronicl existing.

# Checking it

Hand-edited data gets mistakes in it. `cronicl check` reads the tree and reports broken links, people who are their own ancestor, children born before their parents, and that sort of thing, with the file and line of each problem. `cronicl gaps` lists people with missing names, dates or parents, which is handy for figuring out what to look up next.

# The terminal editor

Editing YAML by hand is fine for small changes, but adding a whole branch gets tedious. Running `cronicl` with no arguments opens a terminal app built with [Textual](https://textual.textualize.io/). You type to find people, open one, and edit their record one field at a time. Parents and partners are picked by name from a list, and the list won't offer anyone who would create a loop.

The thing I was most careful about is that it doesn't mess up your file. Nothing is written until it shows you a diff of exactly which lines change, and it only touches those lines. Comments, blank lines and the order of your records stay the way you left them. If the file changed on disk while the editor was open, it won't write at all.

# The website

`cronicl build` turns the tree into a static website: a pan-and-zoom tree, a timeline, a page per person written as a short biography, a list of places, and a "how are these two related?" page. It's plain files, so it can go on GitHub Pages, your own server, or anywhere else that serves static files. It doesn't load any web fonts, scripts or analytics from other sites.

There's a [live demo](https://cbenning.github.io/cronicl/) with a made-up family if you want to click around.

Family trees are full of living people, so there are privacy settings for them: show them, replace them with a placeholder, or leave them out of the site entirely. The build warns you if you're about to publish living people in full.

If you keep photos in [Fussel](/posts/fussel/), the gallery I wrote a while back, cronicl can show a few of each person's photos on their page and link to the rest.

# GEDCOM

If your tree is already in another program, `cronicl import-gedcom` brings it in once. The original file is kept in an `archive/` folder untouched. `cronicl export-gedcom` writes GEDCOM 5.5.1 whenever you want to go back the other way, so you're never stuck with cronicl either.

# Running it

It's a Python package, so:

```bash
uv tool install cronicl      # or pipx install cronicl
mkdir my-family && cd my-family
cronicl init
cronicl                      # open the editor
cronicl serve                # build the site and view it at http://127.0.0.1:8000/
```

The [README](https://github.com/cbenning/cronicl#readme) covers the rest, including how to deploy the site and put it behind a password.
